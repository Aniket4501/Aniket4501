## 🛠️ What I Work On

### ⚡ Performance as a Product Problem

Sometimes the best product improvement isn't a new feature.

My roadmap said engagement. The app took fifteen seconds to open. Anything shipped onto that only ever gets measured on the people patient enough to wait, so I held my own roadmap for eight weeks and put launch time first.

- App launch time: **15s → under 2s**
- Bundle size: **25MB → 6MB**
- Step-sync completion: **+35%**, after the launch-time fix

[Read the case study →](https://aniketagarwal-com.vercel.app/work/step-syncing)

### 🧪 0 → 1

**Steps Premier League** turned step tracking into a competitive season: eight teams of seven, five days, steps scored as cricket runs.

**Session time moved from 3.5 → 7.8 minutes.**

It is also a north star I would not choose again, because a product that works can shorten a session. The case study says so out loud.

[See the live league →](https://spl-hclhc.vercel.app/) · [Read the case study →](https://aniketagarwal-com.vercel.app/work/steps-premier-league)

### 🤖 AI-Powered Products

I took the **AI Smart Health Report** from 0 to 1: the product requirements, the UX flow, and the personalisation logic that decides what an individual report says.

It was designed to turn a page of clinical values into something a non-clinical adult can read, with one prompted next step.

The report was named as a differentiator in **5+ enterprise deals**, and the cross-sell hooks I specified drove **15% incremental revenue**.

### 🔬 What I Build When Nobody Hands Me a Roadmap

**[Grounded](https://aniketagarwal-com.vercel.app/lab/grounded)** is an evaluation harness that scores LLM-generated health summaries against a rubric you can read: grounding, scope, escalation, readability. Every check is a deterministic rule, so it runs in your browser with no model call and no API key.

Its first run disagreed with my own labels on 5 of 16 cases. Most of those were the harness being wrong rather than the labels, and some were my labels moving toward the harness, which is exactly the failure mode an eval set is supposed to prevent. Both versions are still in the repo so a change can be diffed.

[See it run →](https://aniketagarwal-com.vercel.app/lab/grounded) · [Code →](https://github.com/Aniket4501/aniketagarwal.com)

## 🔍 How I Think About Products

**Problem → Evidence → Hypothesis → Build → Measure → Iterate**

Before building anything, I try to answer:

- What problem are we actually solving?
- How do we know it's a real problem?
- Which users hit it hardest?
- What's the smallest thing that tests the hypothesis?
- What metric should move if we're right?
- What did we learn after shipping?
